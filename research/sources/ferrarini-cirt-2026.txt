Abstract.

Refinement types are a powerful mechanism for statically verifying properties of
programs. They have been successfully integrated into practical languages such
as Haskell, Scala, and Rust. However, their metatheory is not yet fully
understood. In this paper we present the first semantic model for a refinement
type system that supports the full feature combination of subtyping, SMT-style
equality, impredicative polymorphism, and (stratified) inductive types.
Interactions between these features have led to inconsistencies in the past, and
existing formalizations of refinement type systems omit at least one of them. We
present a realizability model based on partial equivalence relations (PERs) over
a Scott domain, which overcomes these obstacles. We use our model to prove the
consistency of a core refinement type system and to give a semantic account of
the annotation-independence property of refinement types. Our semantics uses two
interpretations: a refined one, which interprets types and their refinements as
PERs; and an unrefined one, consisting of complete uniform PERs with a bottom
element (CUPERs), which models computational behaviour independently of
refinements. We extend the model to positive and stratified inductive types,
showing that both are consistent in the presence of impredicativity.

1. Introduction

Refinement types (Jhala and Vazou, 2020) extend a host language
with logical predicates that constrain the values inhabiting types. For
instance, the type ⟪\{x\text{:}\mathsf{Int}\,|\,x\neq 0\}⟫ refines the type
of integers, allowing us to statically forbid division by zero. Such systems
have been integrated into practical languages, including Haskell (Liquid
Haskell) (Vazou et al., 2014), Scala
(Stainless) (Hamza et al., 2019), and Rust
(Flux) (Lehmann et al., 2023). Unlike most foundational type
theories, refinement type systems were developed primarily as engineering
artifacts: their design was driven by the goal of verifying existing programs
with minimal disruption to the underlying language, often accepting a degree of
“soundiness” (Livshits et al., 2015) in return for
practicability.

Despite their practical success, the metatheory of refinement types remains only
partially understood. Over the last decade practical refinement type systems
have accumulated several features that interact in non-trivial ways at the
semantic level, and potentially lead to inconsistencies if not handled with
care. For example, 1) subtyping combined with 2) unrefined equality
(i.e. an SMT-style equality that we describe in Section 2.1.2)
and function extensionality has led to inconsistencies in both Liquid
Haskell and F* (Maillard, 2018). Additionally, 3) impredicative
polymorphism combined with some classes of 4) non-strictly positive
inductive definitions as supported in Liquid Haskell can be
shown to be inconsistent in standard type-theoretic
settings (Coquand and Paulin, 1990).

The desire to prevent inconsistency has led to several formalizations of
refinement type systems. For example,
Swamy et al. (2016) prove normalization for a model of
F*, but their calculus has no impredicative polymorphism. Hamza et al. (2019)
prove normalization for a model of Stainless which lacks subtyping.
Ghalayini and Krishnaswami (2023) construct a model for a
system with explicit refinement types, but do not consider inductive types.
Finally, Borkowski et al. (2024) prove type soundness
for a model of Liquid Haskell without higher-order unrefined equalities. As a
result, there is currently no single semantic account that combines the
four key features of refinement types. If we truly want to understand
refinement types and prove their soundness,
we need a semantic model that supports
all of these features simultaneously.

Nevertheless, discovering such a semantic model is challenging. The
set-theoretic semantics given
by Ghalayini and Krishnaswami (2023), which interprets each
refined type as a subset of the interpretation of its erased type,
does not extend to impredicative polymorphism, which has no
set-theoretic model in classical set
theory (Reynolds, 1984a); subtyping and
unrefined equality further constrain how a model can interpret refined
types, as we discuss in Section 2.3. Second, modeling the
non-strictly-positive inductive types of Liquid Haskell is not
straightforward, as they do not have a direct analogue in type theory.

In this paper we present a model based on partial equivalence relations
(PERs) over a Scott domain. In broad strokes, our model follows much of the
standard structure of PER models: types are interpreted as PERs over the domain
and terms as well-defined elements of these PERs
(MacQueen et al., 1986). Thus, the semantic counterpart of
typing is membership in the domain of the PER, and equality is interpreted as
the PER itself. The subtyping relation is interpreted as inclusions between
PERs, so no cast operations are needed. We will show that the notion of
unrefined equality used in refinements may also be modelled by the
unrefined PER interpreting a type. Finally, the PERs offer enough structure to
model impredicative polymorphism in the usual manner, viz. as set-theoretic
intersection over the set of all PERs.

The realizability model that we designed
interprets the key features of refinement type systems
and is
deliberately elementary so that
it can serve as a reference model against which
candidate features are checked before they are
implemented. Concretely, our contributions are:

•

A model of refinement types as they are, not as they are
convenient to model. We isolate four features of practical
refinement type systems (implicit subtyping, SMT-style unrefined
equality, impredicative polymorphism, and non-standard inductive
types) whose interaction is precisely what has caused soundness
bugs in real systems, and we model their combination without
simplifying any of them away. No existing formalization supports all
four (Section 2.2).

•

Modeling unrefined equality. Every type receives
a refined interpretation as a PER, included in an unrefined
interpretation as a CUPER over a Scott domain
(Sections 4, 5 and 6).
This model explains how the SMT-style equality
interacts with higher-order refined terms.
So, our model does not merely avoid the extensionality
inconsistencies of Liquid Haskell and ⟪F^{\star}⟫ , it explains
them: they validate refined equalities that cannot coexist with
unrefined equality (Section 2.1.2).

•

Consistency of positive and stratified inductive types
under impredicativity (Sections 7 and 5.11).
The model shows that positive and stratified types are
consistent in a refined setting even with impredicative polymorphism. Our
techniques are not specific to refinement types: they can be
adapted to any type theory that admits a realizability model, for
example MLTT.
Ours is moreover the first denotational semantics of
stratified indexed types, previously accounted for only by
normalization or step-indexing
arguments (Jacob-Rao et al., 2018; Hamza et al., 2019).
The interpretation of an inductive
type is an initial algebra: folding and unfolding form an isomorphism,
and the eliminator may expose the recursive arguments, in contrast to
Mendler-style weakly initial algebras. So, both positive and
stratified types share a single, uniform introduction and elimination
discipline (Section 7). The message is constructive:
positive and stratified indexed types are a straightforward addition
to refinement systems.

The rest of the paper is structured as follows.
In Section 2 we present the key features of the system,
compare them with existing formalizations,
and explain why they require a
semantic treatment beyond set-theoretic models.
Sections 5, 6 and 7
develop the formal construction of the model CIRT and prove
consistency.
Finally, we present related works and conclude.

Every theorem in this paper is accompanied by a detailed proof in the
supplementary material.

2. Refinement types: Syntax & Semantics

We start (Section 2.1) by presenting the key ingredients of practical refinement type
systems that are relevant for the semantic development of this
paper.
Next (Section 2.2), we describe how these features are
formalized in the literature and summarize their respective
limitations.
Finally (Section 2.3), we derive from these features the
requirements that guide the design of our model.

2.1. Core Features of refinement type systems

A refinement type ⟪\{x\text{:}\tau\,|\,\phi\}⟫ consists of a base type
⟪\tau⟫ , a proposition ⟪\phi⟫ that constrains the values inhabiting
⟪\tau⟫ as the ones satisfying ⟪\phi⟫ .
The language of propositions ⟪\phi⟫ includes boolean-valued
expressions of the host language, equality predicates over terms
(including equality that may not be decidable), and closure under
standard logical connectives.
Refinements are not restricted to base types, but may also appear throughout the type structure, for example in (dependent) function types, polymorphic types, and inductive types.

A key aspect of refinement type systems is that refinements act as an
annotation layer over an existing language: they enrich static checking
while leaving the operational semantics unchanged. This design enables
deployment without runtime overhead, and further ensures that the behaviour of a
program does not depend on refinement annotations. We call the independence of
program behavior from verification annotations the
annotation-independence property.

Refinement type systems are extended with several orthogonal mechanisms that
interact in non-trivial ways at the semantic level. Next, we present the
four main ingredients that appear in practical systems and that are
relevant for the semantic issues studied in this paper.

2.1.1. Subtyping

A refinement that arbitrarily constrains the elements of a type may be
naturally regarded as a subtype of another type; for example, positive
integers are integers. This allows a term to be used at a less-refined or
unrefined type without requiring explicit casts. Semantically, subtyping
expresses inclusion between the meanings of types: every value inhabiting a
subtype must also inhabit its supertype.
Importantly, subtyping is implicit, meaning that, as presented in the
rule Tm-Sub below, no type casts are required to use a term at a
supertype. Function types, in turn, satisfy the standard
contravariant/covariant subtyping rule
Sub-Fun (Cardelli, 1984; Cardelli and Wegner, 1985).

2.1.2. Unrefined equality

Refinements often use equality as an unrefined relation on terms, including
terms of function type. This reflects
the view of the SMT solver, which operates on a representation of these unrefined
terms, and derives equalities without refined type
information (Vazou et al., 2017).

This notion of unrefined equality is the cause of many subtle soundness
questions. For example, function extensionality was introduced in both Liquid
Haskell (Vazou and Greenberg, 2022) and
F* (Maillard, 2018) and later shown to be
inconsistent. The inconsistency arises from the interaction between unrefined
equality and subtyping: in a typed setting, equality is indexed by type and
extensionality can be formulated so as to be harmless; with unrefined equality,
the same axiom has greater force and Vazou and Greenberg (2022) showed that admitting it leads to a proof of false.

2.1.3. Parametric Polymorphism

Most refinement type systems are built on top of languages that have parametric
polymorphism, such as Haskell or Scala. We model such languages through
impredicative type quantification à la System F
(Girard, 1972; Reynolds, 1984b). Thus, a quantified type has the same kind as
the types over which it quantifies. For example, the type
⟪\forall x\text{:}\mathsf{Ty}.\,\mathsf{Int}⟫ itself has kind ⟪\mathsf{Ty}⟫ , and may therefore be
instantiated with arbitrary types of kind ⟪\mathsf{Ty}⟫ , including itself. This
contrasts with predicative polymorphism, where the quantified type lives at a
strictly higher level than the types it quantifies over, in a stratified
hierarchy (Leivant, 1991).

Refinement types should interact smoothly with polymorphism: it should be
possible to refine type variables, instantiate them with arbitrary types, and
quantify over indexed type families.

2.1.4. Non-standard Inductive Types

To preserve consistency, general recursion must be excluded from a system of
refinement types. However, simply replacing it with some flavour of structural
recursion does not suffice, as it is well-known that recursive type definitions
can also be used to encode general
recursion (Pierce, 2002; Harper, 2016). The canonical counterexample is:

⬇

data Bad where MkBad :: (Bad ⟪\rightarrow⟫ Void) ⟪\rightarrow⟫ Bad

where Void is the empty type. This type enables encoding
self-application and yields a contradiction:

⬇

bad :: Bad ⟪\rightarrow⟫ Void worst :: Void

bad (MkBad f) = f (MkBad f) worst = bad (MkBad bad)

This term is a typed instance of Curry’s paradox; that admitting such negative
datatypes breaks normalisation—and hence consistency—in the second-order
⟪\lambda⟫ -calculus is due to Mendler (1987).
While this code is totally valid Haskell, it is rightfully rejected by
Liquid Haskell, which aims to construct a consistent refinement type
system. However, strict positivity is too strong a restriction:
positive types and stratified negative types could be admitted without
compromising consistency.

Positive types.

allow the inductive type to
occur negatively, provided that each
negative occurrence is itself under a negative function arrow; a canonical example is
Hofmann’s routine type (Hofmann, 1993; Berger et al., 2019):

⬇

data Rou where Over :: Rou; Next :: ((Rou ⟪\rightarrow⟫ [Nat]) ⟪\rightarrow⟫ [Nat]) ⟪\rightarrow⟫ Rou

While it is not immediately obvious, the class of positive types can also lead
to inconsistencies in dependently typed systems built on
CIC (Coquand and Paulin, 1990). In contrast, our denotational
model proves that they are harmless in a refinement type system.

Stratified types,

introduced by Jacob-Rao et al. (2018) and
also used by Hamza et al. (2019), are indexed inductive types
whose recursive occurrences appear at ‘strictly smaller indices’ both in
positive and negative positions, ensuring well-foundedness. As an example,
consider the shallow embedding of the simply-typed lambda calculus (STLC) in
Liquid Haskell (from (Ferrarini and Vazou, 2025; Ferrarini et al., 2026))
where the data types Typ and Val, respectively, embed types and values of STLC:

⬇

data Typ = TIota | TArr Typ Typ

data Val where {-@ stratified Val @-}

{-@ VIota :: Int ⟪\rightarrow⟫ Ix Val TIota @-}

VIota :: Int ⟪\rightarrow⟫ Val

{-@ VArr :: t:Typ ⟪\rightarrow⟫ u:Typ ⟪\rightarrow⟫ (Ix Val t ⟪\rightarrow⟫ Ix Val u) ⟪\rightarrow⟫ Ix Val (TArr t u) @-}

VArr :: Typ ⟪\rightarrow⟫ Typ ⟪\rightarrow⟫ ( Val ⟪\rightarrow⟫ Val ) ⟪\rightarrow⟫ Val-\}-\}-\}

The type Typ contains the base type (TIota) and the function type (TArr). The family Val is indexed by such types;
intuitively, Val t contains exactly the values of
object-language type t. The Ix annotation is
Liquid Haskell’s notation for attaching such an index to a datatype.

Ignoring the refinement annotations, Val can be viewed as
the solution of the recursive domain equation of the untyped
⟪\lambda⟫ -calculus, which is sufficiently expressive to encode general
recursion. The refinement annotations, however, equip values with a
type index. A value indexed by TIota must be constructed
using VIota, whereas a value indexed by
TArr t u must be constructed using VArr. The
recursive occurrences of Val appearing in the argument of
VArr are indexed by t and u, which
are strict subcomponents of the result index
TArr t u. Consequently, recursive occurrences only appear
at smaller indices, allowing the family Val to be
interpreted by induction on the structure of the index rather than as
an arbitrary recursive domain equation.
The stratified Val annotation enables the stratification
checker to verify the well-formedness of the type: as explained
in section 8, it checks that the indices of the recursive
occurrences are indeed strictly smaller than the index of the result
type, and accepts the definition of Val.

2.2. Existing formalizations

We give a high-level overview of existing formalizations of refinement type
systems, and the extent to which they model the features described in
Section 2.1. Table 1
summarizes the four formalizations that we
discuss:
⟪\mu F^{\star}⟫  (Swamy et al., 2016)
that models ⟪F^{\star}⟫ ,
System FR (Hamza et al., 2019) that models Stainless,
⟪\lambda_{RF}⟫  (Borkowski et al., 2024) that models Liquid Haskell, and
explicit refinement types (Ghalayini and Krishnaswami, 2023) that models a system with explicit refinement types.
For each system we indicate the extent to which it supports the four features of refinement types, and the semantics used to model them.

Subtyping

Many formal models of refinement types, such
as explicit refinement types and System FR,
do not include explicit subtyping. Instead they rely on a reflection
rule:

⟪[math]⟫

Subtyping is then implicitly possible, as whenever ⟪\phi⟫ implies ⟪\psi⟫ ,
any term ⟪\Gamma\vdash t\text{:}\{x\text{:}\tau\,|\,\phi\}⟫ is also a term of type
⟪\Gamma\vdash t\text{:}\{x\text{:}\tau\,|\,\psi\}⟫ . However, this is not
equivalent to the explicit formulation. To see why, suppose we have a free
variable ⟪f:\mathsf{Int}\to\{x\text{:}\mathsf{Int}\,|\,x\geq 0\}⟫ which we
wish to use as a function of type ⟪\{x\text{:}\mathsf{Int}\,|\,x\geq 0\}\to\mathsf{Int}⟫ . This
cannot be derived from reflection alone, as refinement information
cannot flow through type formers. The eta-expansion
⟪\lambda x.\,f\cdot x⟫ does have this type, a technique that goes back
to Barendregt et al. (1983), but it is a different term from ⟪f⟫ . Explicit subtyping, as
presented in section 2.1.1, is instead designed with specific
rules for each type former, e.g. contravariance on the domain of the
function.

Equality.

Most systems, including those of ⟪\lambda_{RF}⟫ and ⟪\mu F^{\star}⟫ ,
restrict equality to base types, such as ⟪\mathsf{Int}⟫ . This is sound as the refined
equality coincides with the unrefined one on base types. However, it is
too restrictive, as it rules out equalities between higher-order terms
entirely.

In System FR equality is
reduction-based, so that ⟪t\equiv u⟫ if and only if ⟪t⟫ and
⟪u⟫ reduce to a common value. This is untyped and by consequence
also unrefined, but too fine-grained. For example, reduction almost always
uses weak head normal form, and natural equalities at higher-order
types do not hold, e.g. making ⟪\{x\text{:}\mathsf{Unit}\,|\,\lambda y.\,1+2\equiv\lambda y.\,3\}\to\bot⟫ inhabited. Unfortunately,
such equalities arise naturally in refinement types
when encoding the equivalence of terminating functional programs.

In explicit refinement types

equality is the typed ⟪\beta\eta⟫ -equality of the underlying simply-typed
terms; Ghalayini and Krishnaswami (2023) already suggest moving to a
semantics based on partial equivalence relations, which our model also uses.

Polymorphism

⟪\lambda_{RF}⟫ allows the refinement of type
variables, but they can only be instantiated with base types.
Similarly, the calculus of System FR includes indexed
types, but quantification ranges only over fully applied types. As the system
of ⟪\mu F^{\star}⟫ is dependent, they only have
predicative polymorphism: ⟪\forall x\text{:}\mathsf{Ty}.\,\mathsf{Int}⟫ is only a type
at the strictly higher level than ⟪\mathsf{Ty}⟫ , and hence it cannot be instantiated
with itself. Finally, in explicit refinement types there is no
polymorphism.

Inductive types.

In System FR they have step-indexed inductive
types, which are similar to stratified types in the sense
of Jacob-Rao et al. (2018), but they do not have a
direct analogue of positive types. In the rest of the systems there
are no inductive types at all, so no direct analogue of either
positive or stratified types.

2.3. Design requirements for a realizability model

The simplest models of type theories are set-theoretic: types are interpreted as
sets and terms as elements of these sets (Henkin, 1950). The core
features described above impose three requirements on the design of
our model.

The first requirement is support for impredicative polymorphism.
Set-theoretic models of impredicative polymorphism cannot exist because of size
issues (Reynolds, 1984a), at least not within
classical logic (Pitts, 1987).
So our model interprets types as PERs over a fixed domain: these form a set,
so type quantification can be interpreted as an intersection over them.

The second requirement is that subtyping be interpreted as inclusion.
It fails in models that interpret each function type
as the set of all functions between the interpretations of its domain and
codomain: in such a model, subtyping between function types requires cast
operations. For example, type ⟪\mathsf{Int}\to\mathsf{Int}⟫
is interpreted as the set of total functional relations ⟪R\subseteq\mathbbm{Z}\times\mathbbm{Z}⟫ .
Computationally, this type is a subtype of ⟪\{x\text{:}\mathsf{Int}\,|\,x\geq 0\}\to\mathsf{Int}⟫ . However, the latter is interpreted as the set of total functional relations
⟪R\subseteq\mathbbm{N}\times\mathbbm{Z}⟫ . The first set is not a subset of the second, as
it contains pairs ⟪\left\langle n,\,m\right\rangle⟫ with ⟪ncast, discarding the offending pairs. This example exhibits the
general principle of coercive subtyping, which interprets each subtyping
judgment as such a cast inserted at every use of subsumption
(Cardelli and Wegner, 1985). This is unfortunate on two counts. First, the denotation
of a term comes to depend not on the term alone but on the shape of its typing
derivation; this is the classical coherence problem, and well-definedness
can be recovered only by a theorem showing that all derivations of a judgment
agree (Reynolds, 1980; Breazu-Tannen et al., 1991). Second, and more seriously for us,
the cast genuinely removes elements, so that the meaning of a term comes
to depend on the refinements appearing in its type, and annotation-independence is lost. Interpreting subtyping as inclusion requires no
casts (Cardelli, 1984; MacQueen et al., 1986; Frisch et al., 2008). This is the case in
the subset model of refinement types (Melliès and Zeilberger, 2015), where
a refined type is a subset of its underlying type; our model has the same
structure, with PERs in place of raw sets.

The third requirement is that the meaning of a term not depend on the
refinements in its type, so that unrefined equality can observe its behavior
outside them. Unrefined equality cannot be modeled in the presence of the
cast operations described above: a cast removes elements from the
interpretation of a functional term, and there is no way to recover them to
check whether two terms are equal on their unrefined domain.

2.4. Our approach: PERs over a Scott domain

To meet these requirements, we use a model based on partial
equivalence relations (PERs) over a Scott domain ⟪\mathcal{D}⟫ . Our terms
are interpreted as elements of ⟪\mathcal{D}⟫ and types are interpreted as
PERs over ⟪\mathcal{D}⟫ , so that the semantic counterpart of typing is
membership in a PER rather than membership in a set, and the equality
is interpreted by the relation described by the PER itself. The
subtyping relation is interpreted as set inclusion between PERs, so no
cast operations are needed and annotation independence holds
by construction. The unrefined equality can be modeled by carefully
designing the unrefined PERs so that two terms are related by
unrefined equality exactly when they are identified by the unrefined
interpretation of their type. Finally, the PERs offer enough structure
to model impredicative polymorphism as set-theoretic intersection over
the set of all PERs.

3. Background

This section collects the domain-theoretic preliminaries on which our
model rests. We follow the standard accounts of Davey and Priestley (2002),
Abramsky and Jung (1994), Gunter (1992), Amadio and Curien (1998), and
Streicher (2006), to which we refer the reader for proofs.

Definition 0 (PER).

A partial equivalence relation (PER) over a set ⟪A⟫ is a symmetric and
transitive relation over ⟪A⟫ , in other words it is a set ⟪S\subseteq A\times A⟫ such that

(i) if ⟪\left\langle a,\,b\right\rangle\in{}S⟫ then ⟪\left\langle b,\,a\right\rangle\in{}S⟫

(ii) if ⟪\left\langle a,\,b\right\rangle\in S⟫ and ⟪\left\langle b,\,c\right\rangle\in{}S⟫ then ⟪\left\langle a,\,c\right\rangle\in{}S⟫ .

Definition 0 (Domain of a PER).

Given a PER ⟪S⟫ over ⟪A⟫ , its domain is the set of elements of ⟪A⟫
which are related to themselves, i.e. ⟪\mathsf{dom}\left(S\right)=\{a\in A\mid\left\langle a,\,a\right\rangle\in{}S\}⟫ .

Definition 0 (Diagonal PER).

The diagonal PER of any set ⟪A⟫ is given by ⟪\Delta\left(A\right)=\left\{\,\left\langle a,\,a\right\rangle\,\middle|\,\begin{array}[]{c}a\in A\end{array}\,\right\}⟫ .

We will use the notation ⟪\mathcal{PER}\left(A\right)⟫ to denote the set of PERs over
⟪A⟫ . The PER structure will be used to model types, following a long
line of work that interprets types as partial equivalence relations
over a domain or a combinatory algebra
(Abadi and Plotkin, 1990; Amadio, 1991; Cardone, 1989): the domain
of a PER gives us the membership information, while the relation itself
gives us the equality relation. While the definition of a PER does not
give us reflexivity, it satisfies a weaker property that we call
partial reflexivity: if ⟪\left\langle a,\,b\right\rangle\in{}S⟫ then ⟪\left\langle a,\,a\right\rangle\in{}S⟫ .

Definition 0 (Pointed PER).

Let ⟪A⟫ be a set with a distinguished element ⟪\bot\in A⟫ . A pointed PER
over ⟪A⟫ is a PER ⟪S\in\mathcal{PER}\left(A\right)⟫ such that ⟪\left\langle\bot,\,\bot\right\rangle\in{}S⟫

The point will be used to model a nonterminating element, in the manner of
Amadio (1991).

Theorem 3.5 (Knaster-Tarski fixed point theorem).

Let ⟪(L,\leq)⟫ be a complete lattice and ⟪f:L\to L⟫ be a monotone
function. Then the set of fixed points of ⟪f⟫ forms a complete lattice,
and in particular there is a least fixed point ⟪\mathsf{lfp}\,f\,=\bigsqcap\{x\in L\mid f(x)\leq x\}⟫ and a greatest fixed point ⟪\mathsf{gfp}\,f\,=\bigsqcup\{x\in L\mid x\leq f(x)\}⟫ (Tarski, 1955).

Definition 0 (Scott domain).

A Scott domain is a complete partial order that is moreover
⟪\omega⟫ -algebraic and bounded-complete. It is
⟪\omega⟫ -algebraic when every element is the directed least upper bound
of the countably many compact elements below it—an element
⟪c⟫ is compact just if ⟪c\leq\bigsqcup X⟫ for a directed ⟪X⟫ implies ⟪c\leq x⟫ for some ⟪x\in X⟫ . It is bounded-complete when every subset
that has an upper bound has a least upper bound (Scott, 1976; Abramsky and Jung, 1994; Gunter, 1992).

Definition 0 (Chain of projections).

A chain of projections on a Scott domain ⟪D⟫ is an increasing family of
continuous functions ⟪{(\pi_{n})}_{n\in\mathbbm{N}}⟫ , where each ⟪\pi_{n}:D\to D⟫ is
idempotent and below the identity, with ⟪\pi_{0}⟫ the constant function ⟪\bot⟫ ,
and which moreover satisfies ⟪\bigsqcup_{n}\pi_{n}=id⟫ .

Given an element ⟪d\in D⟫ we define the ⟪n⟫ -th approximation of ⟪d⟫ to
be ⟪d_{n}\triangleq\pi_{n}(d)⟫ .

In the rest of this section ⟪D⟫ is a Scott domain equipped with a chain of
projections.

To model types we restrict attention to PERs that interact well with
this order- and approximation structure, in the manner of the ideal
and realizability models of MacQueen et al. (1986),
Abadi and Plotkin (1990), and
Amadio (1991). The
uniformity condition below is the analogue for PERs of their
uniform ideals.

Definition 0 (Complete, uniform, and pointed PERs).

(1)

A PER ⟪S\subseteq D\times D⟫ over a domain ⟪D⟫ is complete whenever
every directed subset ⟪{\{\left\langle a_{i},\,b_{i}\right\rangle\}}_{i\in I}\subseteq S⟫ (with
respect to the product order on ⟪D\times D⟫ ) has a least upper bound
⟪\left\langle\bigsqcup_{i\in I}a_{i},\,\bigsqcup_{i\in I}b_{i}\right\rangle⟫ in ⟪S⟫ .

(2)

A PER ⟪S\subseteq D\times D⟫ over a domain ⟪D⟫ is uniform whenever
for every ⟪\left\langle a,\,b\right\rangle\in S⟫ and every ⟪n\in\mathbbm{N}⟫ we have
⟪\left\langle\pi_{n}(a),\,\pi_{n}(b)\right\rangle\in S⟫ .

(3)

In this paper, a CUPER is a pointed, complete, and uniform PER. We write
⟪\mathcal{CUPER}\left(D\right)⟫ for the collection of such PERs over a domain ⟪D⟫ .

Completeness asks that a type be closed under the directed least upper bounds
of ⟪D\times D⟫ , so that the limits along which recursive computations
converge remain within it and least fixed points can be interpreted there
(Amadio, 1991). Uniformity asks instead
that membership be stable under approximation: a related pair remains related
at every stage ⟪\pi_{n}⟫ . In the presence of completeness, an element
then belongs to a type exactly when all of its approximations do.

Recursive and inductive types will be interpreted as fixed points
(section 7). We adapt the contractive construction
of Amadio (1991): because
⟪\bigsqcup_{n}\pi_{n}=id⟫ , a CUPER is determined by its
approximations, and a contractive operator—one that sharpens agreement
by one approximation per unfolding—has a unique fixed point.

Definition 0 (Approximation of a relation).

The ⟪n⟫ -th approximation of a relation ⟪A\subseteq D\times D⟫ is its
pairwise image under the ⟪n⟫ -th projection,
⟪A_{n}\triangleq\left\{\,\left\langle\pi_{n}(v),\,\pi_{n}(w)\right\rangle\,\middle|\,\begin{array}[]{c}\left\langle v,\,w\right\rangle\in A\end{array}\,\right\}⟫ .

Lemma 3.10 (Restriction).

Let ⟪S⟫ be a CUPER over ⟪D⟫ and write ⟪D_{n}\triangleq\pi_{n}(D)⟫ . Then ⟪S_{n}=S\cap(D_{n}\times D_{n})⟫ . Consequently each ⟪S_{n}⟫ is a pointed PER, and ⟪S_{j}\subseteq S_{n}⟫ whenever ⟪j\leq n⟫ .

Lemma 3.11 (A CUPER is determined by its approximations).

If ⟪A⟫ and ⟪B⟫ are CUPERs over ⟪D⟫ with ⟪A_{n}=B_{n}⟫ for all ⟪n⟫ , then ⟪A=B⟫ .

Definition 0 (Non-expansive and contractive operators).

An operator ⟪\Phi:\mathcal{CUPER}\left(D\right)\to\mathcal{CUPER}\left(D\right)⟫ is non-expansive when ⟪A_{n}=B_{n}⟫ implies ⟪\Phi(A)_{n}=\Phi(B)_{n}⟫ for all ⟪n⟫ , and contractive when
⟪A_{n}=B_{n}⟫ implies ⟪\Phi(A)_{n+1}=\Phi(B)_{n+1}⟫ for all ⟪n⟫ .

Lemma 3.13 (Contractive fixed point).

Every contractive operator ⟪\Phi:\mathcal{CUPER}\left(D\right)\to\mathcal{CUPER}\left(D\right)⟫ has a unique fixed
point.

A central feature of our model is that every type is equipped with two
semantics:

•

The refined semantics, which interprets types as PERs over
⟪\mathcal{D}⟫ and respects refinements.

•

The unrefined semantics, which interprets types as CUPERs over
⟪\mathcal{D}⟫ , ignoring refinements.

Following Amadio (1991), the distinguished
bottom element will account for non-termination and general recursive types that
are present in the unrefined semantics.

The two semantics will be related by inclusion: the refined interpretation of
each type will be included in its unrefined interpretation. This reflects the
intuition that refinements only add logical information without changing the
underlying computation. Several constructions in the model, notably function
types and equality predicates, rely on the interaction between these two layers.

Since types may be indexed by terms, kinds cannot be interpreted
merely as syntactic classifications. Instead, kinds will be interpreted
set-theoretically as collections of PER-valued functions respecting
the PER structure of their arguments. Context interpretations
therefore store both term-level information and type-level information
together with projections connecting the refined and unrefined worlds.

7. Inductive types

Finally, we extend the calculus of Section 6
with inductive types. We add kinds for inductive type constructors and
formation rules for inductive types, reflecting index dependence.

The central question of our design is which recursive occurrences of an
inductive type should be allowed so that its semantic interpretation remains
well defined.
Strict positivity is the familiar discipline from
dependent type theory: a datatype such as lists is accepted because
recursive occurrences appear only on the right of the function
type. Refinement systems also use two broader
patterns. Positive inductive types allow non-strictly-positive shapes
whose overall variance is still covariant. Stratified inductive types
allow recursive occurrences at smaller indices, even in negative
positions.

Strictly positive inductive types admit an elegant canonical syntactic
presentation in terms of W-types, which capture constructions
generated by strictly positive signatures. However, positive and
stratified inductive types allow more general shapes that are not
reducible to standard strictly positive signatures. For this reason
inductive types will be presented via a general axiom schema.

Section 7.1 presents the syntax of indexed
kinds, positive and stratified inductive types, and the typing rules
for introduction and elimination, in particular both positive and
stratified types use a single general introduction rule and
elimination schema. Section 7.2 presents
the semantics of indexed kinds and inductive types and prove that the
semantics of the eliminator is well defined and satisfies the
semantics of the typing rules.

7.2.3. Refined inductive types.

The refined semantics instead uses more traditional techniques from
the semantics of inductive types: for positive inductive types the
type operator is monotone and the Knaster-Tarski theorem yields a
least fixed point; for stratified inductive types the well-founded
order over the indices yields a unique, hence least, fixed point by a
bottom-up construction. These arguments discharge the new induction
cases of theorem 5.3.
For least to be meaningful we order the semantics of types by
the pointwise lift of PER inclusion and the semantics of kinds by
inclusion.

To permit positive types, we simply relaxed
the existing strictly positivity check.
The encoding of stratified inductive types is more involved, as Liquid Haskell does not have a direct support of indexed inductive types.
Yet, following the technique of data propositions (Borkowski et al., 2024),
stratified types can compile to ordinary inductive types, by encoding the index information in the refinement logic,
via an uninterpreted function.

Finally, we implemented a stratification condition that ensures that the well-formedness
condition of the declaration is satisfied.

Stratification is checked when a datatype

in Liquid Haskell, it required

9. Related work

Models of refinement type systems.

Refinement types were introduced by Freeman and
Pfenning (Freeman and Pfenning, 1991) as a discipline for
carving out subsets of ML datatypes. Stating properties of data by
predicates over unindexed types, as refinement types do, has a long history in
logic-enriched type theories (Gambino and Aczel, 2006; Adams and Luo, 2010). In Sections 2.1 and
2.2 we already discussed in detail what
is and what is not captured by existing formalizations of refinement
type systems. Other works, such
as (Bovel et al., 2026), build
on (Hamza et al., 2019) by reintroducing a subtyping
judgment, validating its necessity. However, they establish only a
partial correctness result relative to termination and do not
guarantee consistency. Lepigre (2016) gives a classical realizability
model of a second-order language with impredicative polymorphism and an
equality type on untyped terms, interpreted as observational equivalence of
programs rather than by the unrefined interpretation of a type; it has neither
subtyping nor inductive types. Closest to ours in spirit is the work of Economou et al. (2023), who
likewise give an elementary domain-theoretic denotational semantics
for a refinement type system with subtyping and use it to derive
logical consistency. Their system, however, belongs to the
index-refinement tradition of Dependent ML and liquid
types (Rondon et al., 2008): it
supports neither impredicative polymorphism nor the non-standard
inductive types that are our central concern.
The view of refinements as an annotation layer
over an unrefined language is made precise by Melliès and Zeilberger (2015), who axiomatise a
refinement type system as a functor from a category of refined typing
derivations down to its unrefined base. Our dual-layer
model—refined PERs sitting above a layer of CUPERs that models
computation—is a semantic instance of this picture: a type denotes a PER
over ⟪\mathcal{D}⟫ included in a CUPER over ⟪\mathcal{D}⟫ , a term denotes an element of
⟪\mathcal{D}⟫ preserving both relations, and annotation independence is its
concrete manifestation. Methodologically, our
interpretation of types as PERs follows the recipe
of Harper (1992) for constructing type systems over
an operational semantics, with the closed terms replaced by the elements of
⟪\mathcal{D}⟫ .

Models of System F

Interpreting types as PERs over a universal domain is a standard technique of
realizability (Abadi and Plotkin, 1990; Amadio, 1991; Bruce and Mitchell, 1992).
We build on the model of System F with general inductive types given
by Amadio (1991), which
interprets types as CUPERs over a domain and itself descends from the
ideal model of MacQueen et al. (1986). Those models solve
recursive type equations by a Banach (1922) contraction on a
metric of relations; we adapt the same contractive argument to the
minimal-invariant projections of the domain (Pitts, 1996), avoiding
the metric. Birkedal et al. (2007) obtain recursive types in admissible PERs
from parametricity instead.

Stratified inductive types.

Jacob-Rao et al. (2018) introduce
stratified types as a way to circumvent the absence of large
elimination in Tores. Their system omits
impredicative polymorphism,
subtyping, and refinement types, and instead supports general
recursive types via Mendler (1991)-style
recursion. Their development also
includes a normalization proof. Our work can be seen as extending this
setting with impredicative polymorphism and refinement structure. The
strategy of relaxing syntactic strict positivity in an impredicative
setting goes back to Matthes (1999),
who replaces positivity with a monotonicity witness while retaining
strong normalization for System F extended with fixed-point types.
Sized types (Abel, 2008) index an inductive type by an ordinal that
bounds the height of its elements, in order to check termination. Sizes
form a dedicated kind, the operator must be monotone, and types do not depend
on terms.
Abel (2012) notes that the size-indexed approximants remain well defined
for a non-monotone operator, but does not study the metatheory of that case.

Dependent type theory.

In contrast to refinement types, standard dependent type theories,
such as the Calculus of Inductive Constructions enforce strict
positivity requirements for inductive definitions. This restriction is
fundamentally necessary in standard type theory to preserve logical
consistency, particularly when combined with impredicative
polymorphism, as demonstrated by the Coquand and Paulin (1990) paradox. Furthermore,
systems with large elimination allow for the construction of power
sets from inductive types, making non-strictly positive definitions
inherently dangerous. Our PER-based semantics demonstrates that, in a
refinement setting without large elimination, this strict requirement
can be safely relaxed.

10. Conclusion & Future Work

We presented a semantic model for refinement type systems based on
partial equivalence relations over a Scott domain. The model accounts
for all subtyping, unrefined equality, impredicative
polymorphism, and non-standard inductive types, and
comes with PER-respecting interpretations.

This realizability model shows
that the core refinement type calculus is consistent, even in the presence of positive and
stratified inductive types.
These two inductive type schemes are currently
permitted by Liquid Haskell and we believe that the same design can guide future
extensions of more expressive type systems.

Our refinements express total correctness: a term of a refined type
terminates and satisfies its predicate. Refined types are therefore
ordinary PERs and need not contain a bottom element, whose presence
under lazy evaluation makes the refinement logic
inconsistent (Vazou et al., 2014).
Partial correctness and quotient types would require a different
model, in both cases because equality is unrefined. Partial correctness
requires the refined semantics of types to be complete (Crary, 1998),
which is not the case in general. Quotient types (Hewer and Hutton, 2024)
identify more elements than unrefined equality does, which contradicts
Theorem 5.5.

Our proofs are not mechanically verified. A complete mechanization
would require formalizing the underlying domain theory, the
PER/CUPER constructions, and the semantic interpretation of the
inductive types introduced in this work. While mechanized
developments of syntactic metatheory are more common, mechanizations
of semantic models at a comparable level of expressiveness remain
an active research field. Developing the semantic
infrastructure and carrying out the corresponding soundness proofs
would constitute a substantial project in its own right.

Appendix B Elimination examples

B.1. Negative inductive types are still inconsistent

If the type declaration of Bad (Section 2.1.4)
were allowed, where ⟪\bot⟫ is an empty type:

⟪\mathsf{Bad}:\mathsf{Ty}\triangleq\mu\,\mathsf{B}^{\left\langle+\right\rangle}\left\{\,\mathsf{MkBad}\text{:}(\mathsf{B}\to\bot)\to\mathsf{B}\,\right\}.⟫

The eliminator for Bad would have type

⟪\mathit{elim}_{\mathsf{Bad}}\left(c_{\mathsf{MkBad}}\right):(b\text{:}\mathsf{Bad})\to\rho(b),\text{where}⟫

⟪c_{\mathsf{MkBad}}:(f\text{:}\mathsf{Bad}\to\bot)\to(\mathsf{Bad}\to\mathsf{Unit})\to\rho(\mathsf{MkBad}\ f)⟫

We can show that ⟪\mathsf{Bad}⟫ must be empty: instantiating the
motive at the constant type ⟪\rho(b)\triangleq\mathsf{Bad}\to\bot⟫ ,
the eliminator has type ⟪\mathsf{Bad}\to\mathsf{Bad}\to\bot⟫ , and
diagonalizing gives

⟪notBad:\mathsf{Bad}\to\bot\triangleq\lambda\;b.\;\mathit{elim}_{\mathsf{Bad}}\left(\lambda\;f\;g.\;f\right)\,\,b\,\,b⟫

But, at the same time, show that it is inhabited

⟪bad:\mathsf{Bad}\triangleq\mathsf{MkBad}\ notBad⟫

Hence, deriving a contradiction.

⟪contra:\bot\triangleq notBad\,\,bad⟫

The inconsistency arises because the eliminator exposes recursive
occurrences of Bad directly. Mendler-style recursion, by contrast, hides
those occurrences, preventing such self-application arguments and
preserving normalization even for datatypes that are not positive.

Appendix C Weakening, substitution and narrowing

We use the notation ⟪\Gamma\vdash J⟫ to mean any of the judgments
⟪\Gamma\vdash\kappa\text{:}\mathsf{Kd}⟫ , ⟪\Gamma\vdash\tau\text{:}\kappa⟫ , ⟪\Gamma\vdash t\text{:}\tau⟫ ,
⟪\Gamma\vdash\phi\;\mathsf{prp}⟫ , ⟪\Gamma\vdash\tau\preceq\sigma⟫ .

As usual, we have weakening and substitution lemmas for the syntactic
judgments, which are proved by induction on the derivation. The
weakening lemma is used in the proof of the substitution lemma.

Lemma C.1 (Weakening).

Let ⟪\Gamma,\,x\smash{:_{\scalebox{0.45}{T}}}\tau,\,\Delta⟫ (resp. ⟪\Gamma,\,x\smash{:_{\scalebox{0.45}{K}}}\kappa,\,\Delta⟫ ) be a well-formed context,
with ⟪x⟫ fresh. If ⟪\Gamma,\,\Delta\vdash J⟫
is derivable, then so is the
corresponding judgment over the enlarged context
⟪\Gamma,\,x\smash{:_{\scalebox{0.45}{T}}}\tau,\,\Delta\vdash J⟫ (resp. ⟪\Gamma,\,x\smash{:_{\scalebox{0.45}{K}}}\kappa,\,\Delta\vdash J⟫ ).

Proof.

By induction on the derivation. Every rule is closed under inserting
an unused binding: extend ⟪\Delta⟫ every time a rule introduces a
binder.
∎

Appendix D Domain theory

Definition 0 (Complete lattice).

A complete lattice is a partially ordered set ⟪(L,\leq)⟫ such that
every subset ⟪S\subseteq L⟫ has a least upper bound ⟪\bigsqcup S⟫ and
a greatest lower bound ⟪\bigsqcap S⟫ in ⟪L⟫ .

Definition 0 (Complete partial order).

A complete partial order (CPO) is a partially ordered set ⟪(P,\leq)⟫
such that every directed subset ⟪D\subseteq P⟫ has a least upper
bound ⟪\bigsqcup D⟫ in ⟪P⟫ .

A CPO is pointed if it has a least element ⟪\bot\in P⟫ .

Definition 0 (Monotone function).

Given two partially ordered sets ⟪(P,\leq_{P})⟫ and ⟪(Q,\leq_{Q})⟫ , a
function ⟪f:P\to Q⟫ is monotone if for all ⟪p_{1},p_{2}\in P⟫ , if
⟪p_{1}\leq_{P}p_{2}⟫ then ⟪f(p_{1})\leq_{Q}f(p_{2})⟫ .

Definition 0 (Continuous function).

Given two complete partial orders ⟪(P,\leq_{P})⟫ and ⟪(Q,\leq_{Q})⟫ , a monotone
⟪f:P\to Q⟫ is continuous if for every directed subset ⟪D\subseteq P⟫ ⟪f(\bigsqcup D)=\bigsqcup f(D)⟫ .
