The default environment, stdlib , names each function module/function . Functions check their arguments. A call with an argument of the wrong kind fails and says which argument, what the function takes there, and what it got, as in "number/add" takes a number as argument 1 but got "one". Each says how many arguments it takes, and a call with any other number fails in the same form, as in "number/subtract" takes 2 arguments but got 3. Each module's example below calls every function in the module.
Every function waits when it is called with a logic variable among its arguments, so all of them work as filters and computed values in rules and queries. A function that is given a goal gets its answer, true or false ; see Asking questions . Functions of the aggregate and graph modules take logic variables as they are, to build aggregates and goals.
number
Every argument must be a number. Lion's numbers are JSON numbers, so arithmetic whose result is not a finite number, such as division by zero or an overflow, fails with ArithmeticError . Integers a JSON number holds exactly, up to 2^53 - 1 either side of zero, do exact arithmetic: a sum, difference, product, or power of them that a JSON number cannot hold exactly fails with ArithmeticError too, instead of rounding. Past that range a number is a float, and rounds as one.

schema
Checks values against schemas, and builds schemas out of others. Anything is a schema; see What fits a schema . The functions that check take the value first, then the schema. schema gives a schema a name.
Function Returns
["schema/fits?", value, schema] Whether the value fits the schema. With a logic variable in it, it is a goal that also binds the variables of the schema, and binds the value to each value the schema allows when the schema can list them; see Patterns .
["schema/problems", value, schema] Every place where the value does not fit, in the order of their paths; an empty list when it fits. A problem is a record with a path , the keys and positions that lead to the part. A part with the wrong value has what was expected , a schema written as the expression that makes it, and what was found . A part that is missing has only expected , and a key the schema does not name has only found .
["schema/includes?", a, b] Whether every value a allows fits b : decided exactly, by listing a 's values when it can list them and by the solver otherwise. Fails, and says why, when neither can decide it.
["schema/assert", value, schema] The value, when it fits. When it does not, fails with a message that says where. As a value in a rule or find , it fails the query that runs it.
["schema/anyOf", schema, ...] A schema that fits a value which fits at least one of the schemas. Of plain values it is a list of choices. It reports one problem, at the value that fits none.
["schema/allOf", schema, ...] A schema that fits a value which fits every one of the schemas. It reports the problems of each schema the value does not fit.
["schema/arrayOf", schema]
["schema/arrayOf", schema, most] A schema that fits a list whose every item fits the schema. With most , a whole number, the list has at most that many items, so a schema whose items can be listed lists every such list.
["schema/recordOf", schema] A schema that fits a record whose every value fits the schema
["schema/optional", schema] As the schema of a record's key, lets the key be left out; a key that is there must fit. Anywhere else it is the schema itself.
["schema/open", record]
["schema/open", record, rest] A schema that fits a record which fits the record of schemas, or the named schema of one, whatever other keys it has. With rest , the record of its other keys must fit rest . A list of schemas works the same way, with the items after the ones it names as the rest. A record or list of schemas on its own leaves nothing for its rest.

quantity
Numbers that carry their units, checked when the program runs, as Pint checks them. A quantity is data: a record of a value and a unit , the unit a record from each base unit's name to its whole exponent, so {"value": 15, "unit": {"m": 1, "s": -1}} is 15 metres a second. A plain number is a quantity with no unit, and a result with no unit left is its plain number. Units are equal when their records are; to convert, multiply by a quantity such as {"value": 1000, "unit": {"m": 1, "km": -1}} . A quantity is a record, so a schema says what unit a value has: {"value": "value/number?", "unit": {"m": 1}} .

aggregate
Called on a list, each function combines the list. Called on anything else, it waits for the list its argument turns out to be; a find is the list of what it found. Only as a whole argument of a rule's head, and not on a find , it combines one value from each of the rule's matches instead, grouped by the head's other columns; see Summarize groups of facts . A sum is rounded once, so adding the same numbers in another order, as the matches of a rule or the candidates of a key may come, gives the same number:

graph
Algorithms over an edge relation whose first two columns are from and to. Each call is a goal: give the edge relation, any other inputs, then one term per output column. An input is a value, or a variable that another goal binds; the algorithm then runs once for each value. Results never depend on the order facts were added.
Goal Rows
["graph/shortestPath", edges, start, to, cost, path] Dijkstra's algorithm from start , in order of cost, starting with start itself at cost 0. A third edge column is the weight, at least 0; without one, each edge costs 1.
["graph/pageRank", edges, node, rank] PageRank with damping 0.85, rounded to 6 decimal places. Ranks add up to 1.
["graph/components", edges, node, component] Connected components, ignoring direction, named after their smallest node
["graph/stronglyConnected", edges, node, component] Strongly connected components, named after their smallest node
["graph/topologicalOrder", edges, node, position] Positions from 0 in a topological order, or an error that names a cycle
