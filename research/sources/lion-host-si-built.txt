Gaps: 7 tasks Lion cannot express yet
  sicp-1.2.1-factorial-exact: Lion's numbers are exact integers only from -(2^53 - 1) to 2^53 - 1; a whole number past that is a float, so 25! comes out as 1.5511210043330986e+25, not 15511210043330985984000000. The exact-numbers research run (branch claude/clef-language-lion-insights-e4faf9) weighs exact numbers that would close this.
  r7rs-6.7-string-reverse-by-characters: Lion's strings count and split UTF-16 code units, as JavaScript does, and Lion has no function on characters: string/split with "" breaks "𝄞" into two halves, so its characters cannot be reversed without telling surrogates apart through a side channel such as object/json-stringify, which would be bending the task.
  datalog-win-move-well-founded: Lion's rules allow only stratified negation: a rule cannot ask a question about a relation that depends on its own head, so win(x) :- move(x, y), not win(y) is refused, and the well-founded semantics that tells won, lost, and drawn positions apart is not built. Computing it by hand with an alternating fixpoint in plain code would be bending the task.
  lion-schema-inclusion-across-kinds: schema/includes? fails instead of giving false when the first schema allows values the solver cannot stand for: value/number? in value/integer? fails with "The solver cannot reason about value/integer?", value/string? in value/number? because value/string? says no kind, and a schema/open record in an exact one because the open rest allows any other keys.
  bounded-sorting-correct: Lion's solver works a lambda out by its body, but not a lambda that calls itself, so it cannot follow a recursive sort such as insertion sort over a list that schema/arrayOf stands for; the goal fails with "?xs stands for infinitely many values".
  induction-sum-of-odd-numbers: Lion's solver decides linear arithmetic over numbers and whole numbers, and reasons about lists of bounded length. A claim about every n needs induction over an unbounded sum, and n * n multiplies two unknowns, so neither is decided.
  induction-sorting-every-length: Lion proves claims about lists of bounded length, which schema/arrayOf with a most stands for; a claim about lists of every length needs induction, which the solver does not do.
