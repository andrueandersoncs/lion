**Most worth Lion's attention**
1. Reactive Signals' "surface, not engine". Signal is to fact as Memo is to rule-derived value, and Effect to a watched query. Plain-code memos and effects could be sugar over Lion's existing incremental relation engine, so there is one engine rather than two. The "one node type for sources and computed values" point also supports keeping Lion's one relation model.
2. The rule that cutoff never erases an independent invalidation, with its example A = X%2, B = Y, C = A+B. Clef states it as normative, and it can be used directly as a property for batched changes and for any memo.
3. Demand gating: recompute only what is both stale and demanded. Demand would be counted per consumer, like a weight, so one watcher leaving keeps the relation maintained for the others. Today Lion maintains every derived relation.
4. Dependencies from actual reads, which can change on every run (the showFirst example). A recomputation that fails or waits partway must not publish the dependencies it collected so far, which ties memos to Lion's Pending protocol.
5. Events versus state. Observables deliver every emission and only drop duplicates through an explicit operator. Lion's set-valued relations merge equal facts by construction, so event input would need an explicit decision.
6. Promises (delay/force): they must memoize (Clef's own first prototype recomputed on every force), and Lion would need to choose rules for reentrant forcing and a body that raises.
7. Coeffects as a union semilattice over requirements. Lion's "wait until bound" is already one such requirement, and Lion's own rules could derive the rest over the AST.
8. Information accrual: a carried fact keeps its premises, and a "constructed witness" re-checks a fact at an open boundary. These match Lion's `why`/weights and its schema argument guards. Structural sharing could make `assuming` cheap.

**Limits and trade-offs the pages admit**
- Cutoff gives no fixed bound on work or time, staleness marking is conservative, and no distributed stabilization protocol is specified (Incremental, Observable).
- Purity does not establish confluence, independence or permission to reassociate arithmetic (Referential Transparency). For Lion this matters for floating-point aggregates maintained incrementally.
- Reentrant forcing and failed initialization of lazy values are unsettled. Laziness costs space leaks and memory bandwidth (Why Lazy Is Hard).
- Coeffects and Codata, Collect Yourself and the regime parts of Referential Transparency are largely proposals: "future work, not yet implemented", "potential" gains, "some day". "Coeffect inference is deterministic and complete" is asserted, not shown.
- Managed Mutability is a February 2026 snapshot that calls itself "not current conformance evidence". In it, mutable variables captured by escaping closures compiled to dangling pointers.
