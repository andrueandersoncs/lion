**Ideas most worth Lion's attention**
1. **One continuation primitive.** Use delimited continuations with lexically fixed delimiters (dcont-spec, delimited-continuations). Clef runs async, actors and generators on one structure that differs only in what resumes it. Lion could put its Pending resumption, generators and host async on the same primitive. The frame is the same object as a closure environment, and the JS-host rule maps cuts onto host generators or async.
2. **Deadlock checking as a relation.** The wait-for relation is a sound over-approximation and the proof is a rank constraint. Its unsat core is the cycle, which is also the diagnostic. This is a two-rule Datalog program for Lion and has the same shape as `why`: the failing proof and the message are one object. Each site gets one of three grades (proved silently, proved with an inferred witness, visibly downgraded).
3. **A fixed point with an unresolved premise establishes nothing (Baker).** This matches Lion's `assumed` over unknowns. Baker is elaboration (expanding higher-order functions into primitive subgraphs) plus a fixed point over facts. It is not egg-style equality saturation.
4. **Provenance.** Synthesized nodes carry origin tags and an expansion id (PSG), and relations keep their participants and premises (PHG). Both support Lion's `why` and showing desugared code apart from source.
5. **Reachability as rules, plus a causal delta cone across revisions.** This would give Lion incremental re-analysis of only the definitions an edit affects, in the REPL.
6. **One schema per nanopass language**, with a property test per pass, which would bring Keep and Dybvig's guarantee into Lion's fitting rule.
7. **Explicit interactive session semantics.** Keep checked, executed, stale and unresolved results apart, and state what a REPL `define` does to closures that captured the old binding.

**Limits and trade-offs the pages state**
- **Deadlock:** the guarantee covers only the statically resolvable fragment. Acyclicity over value-carried routing is undecidable, and the may-wait relation flags cycles that no run reaches. CP/HCP forbid non-tree topologies, Priority CP priorities are non-local, and the page says Clef is not deadlock-free "without qualification".
- **Continuations:** the default is one-shot, and multi-shot must be declared, which is the opposite of what logic search needs. Static delimiters rule out dynamic handler lookup. Keeping continuation structure is said not to make compilation faster by itself. A contract correction (26 September 2026) withdrew an earlier stack-allocation example.
- **Baker:** the ingredient boundary is kept by review only, a recipe existing does not prove coverage, and reaching a fixed point does not prove productivity.
- **PHG:** the temporal-learning material is a schematic research direction, and the page says the graph alone establishes neither a schedule nor a performance gain.
- **Metaprogramming:** the framework is self-described as early-stage. The claim that OCaml PPX is string-based looks wrong to me (PPX rewrites the parse tree), so treat it as unreliable.
- **Nanopass:** Composer does not use the nanopass framework and claims "similar guarantees" from F# features, without the framework's generated checks.
- **Introduction:** large parts are the F# spec's own text, so its claims describe F# as much as Clef.
- **Throughout:** many statements are normative spec text or phrased as "is designed to", so they describe intended designs, not demonstrated implementations.
