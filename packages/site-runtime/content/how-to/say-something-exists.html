This guide shows how to say that something exists when nobody has said what it is, such as a mother for every person or a lead for every team, and how to work with the values Lion invents for it.

Write a rule that invents

List a variable of the head in exists. The head then holds for some value of it that nobody has given, and the rule invents that value, an unknown:

["begin", ["relation", "person", ["name"]], ["relation", "mother", ["child", "mother"]], ["fact", ["person", "ada"], ["person", "ben"], ["person", "cy"]], ["fact", ["mother", "ada", "eve"]], ["rule", ["exists", ["?m"], ["mother", "?c", "?m"]], ["person", "?c"]], ["query", ["mother", "?child", "?mother"], {"order": "child"}]]

The rule invents only for an answer whose head does not hold already. Ada has a mother, so it invents nothing for her. Without exists, a head variable that the body never binds is an error, and the message suggests exists.

Rules that invent wait until every rule that invents nothing has finished. Here the rule that reads birth records is written after the rule that invents, and still gives ben his mother first, so nothing is invented for him:

["begin", ["relation", "person", ["name"]], ["relation", "birth", ["child", "mother", "year"]], ["relation", "mother", ["child", "mother"]], ["fact", ["person", "ada"], ["person", "ben"]], ["fact", ["birth", "ben", "fay", 1990]], ["rule", ["exists", ["?m"], ["mother", "?c", "?m"]], ["person", "?c"]], ["rule", ["mother", "?c", "?m"], ["birth", "?c", "?m", "?_"]], ["query", ["mother", "?child", "?mother"], {"order": "child"}]]

So the result never depends on the order rules or facts were added in.

Read an unknown

An unknown is written ["some", "?m", ["mother", "ben", "?m"]]: the value ?m stands for in a row ["mother", "ben", ?m]. That form is ordinary Lion. Evaluating it gives the same unknown, so a program can write one to put it in a fact, look it up, or compare it:

["begin", ["relation", "person", ["name"]], ["relation", "mother", ["child", "mother"]], ["relation", "tall", ["name"]], ["fact", ["person", "ada"], ["person", "ben"]], ["fact", ["mother", "ada", "eve"]], ["rule", ["exists", ["?m"], ["mother", "?c", "?m"]], ["person", "?c"]], ["fact", ["tall", ["some", "?m", ["mother", "ben", "?m"]]]], {"ben's mother is it": ["mother", "ben", ["some", "?m", ["mother", "ben", "?m"]]], "children of tall mothers": ["find", "?c", ["and", ["mother", "?c", "?m"], ["tall", "?m"]]], "is it eve": ["=", ["some", "?m", ["mother", "ben", "?m"]], "eve"], "unknown?": ["find", ["array/make", "?c", ["value/unknown?", "?m"]], ["mother", "?c", "?m"]]}]

An unknown equals itself and nothing else, as a string does, and two unknowns are the same when they are written the same way. It sorts after every record. A function that needs a number or a string fails on one, as it does on any value of the wrong kind.

Keep only known answers

value/unknown? is true for an unknown, so ["not", ["value/unknown?", "?m"]] keeps only the answers whose values were given. Lion stays closed-world: not holds for anything that is not known, so ben's unknown mother is not eve:

["begin", ["relation", "person", ["name"]], ["relation", "mother", ["child", "mother"]], ["fact", ["person", "ada"], ["person", "ben"]], ["fact", ["mother", "ada", "eve"]], ["rule", ["exists", ["?m"], ["mother", "?c", "?m"]], ["person", "?c"]], {"known": ["query", ["and", ["mother", "?child", "?m"], ["not", ["value/unknown?", "?m"]]]], "not eve": ["find", "?child", ["and", ["mother", "?child", "?m"], ["not", ["=", "?m", "eve"]]]]}]

Ask whether something exists

exists is also a goal: it holds when its goal holds for some value of each variable it lists. Those variables are its own wherever it stands, so they never appear in an answer. It is a question, so it works in plain code, in a query or rule, under not, and in a find:

["begin", ["relation", "person", ["name"]], ["relation", "mother", ["child", "mother"]], ["relation", "tall", ["name"]], ["fact", ["person", "ada"], ["person", "ben"], ["person", "cy"]], ["fact", ["mother", "ada", "eve"], ["mother", "ben", "fay"], ["tall", "eve"]], {"has a tall mother": ["query", ["and", ["person", "?p"], ["exists", ["?m"], ["and", ["mother", "?p", "?m"], ["tall", "?m"]]]]], "has no mother": ["find", "?p", ["and", ["person", "?p"], ["not", ["exists", ["?m"], ["mother", "?p", "?m"]]]]], "anyone with a mother": ["exists", ["?c", "?m"], ["mother", "?c", "?m"]]}]

Invent one value for several rows

A head can be an and of relation calls, which adds a row to each. Under exists, one unknown is in every row, and the goal of its some is the whole and. Here every team has a lead who is on the staff. The web team's lead already is, so nothing is invented for it:

["begin", ["relation", "team", ["name"]], ["relation", "lead", ["team", "person"]], ["relation", "staff", ["person"]], ["fact", ["team", "web"], ["team", "data"]], ["fact", ["lead", "web", "ana"], ["staff", "ana"]], ["rule", ["exists", ["?p"], ["and", ["lead", "?t", "?p"], ["staff", "?p"]]], ["team", "?t"]], {"leads": ["query", ["lead", "?team", "?person"], {"order": "team"}], "staff": ["find", "?p", ["staff", "?p"]]}]

With several variables, exists invents an unknown for each. The goal of each some mentions the others, which are its own too:

["begin", ["relation", "person", ["name"]], ["relation", "parents", ["child", "father", "mother"]], ["fact", ["person", "ann"]], ["rule", ["exists", ["?f", "?m"], ["parents", "?c", "?f", "?m"]], ["person", "?c"]], ["query", ["parents", "?child", "?father", "?mother"]]]

Make unknowns one with a key

A key says a relation has one row per key. When two rows have the same key and differ only where one holds an unknown that the relation's rules invented, the unknown takes the other row's value: a given value, or, when both are invented unknowns, the one that sorts first. Here every person has a mother and twins share one, so ben and cy get one unknown mother:

["begin", ["relation", "person", ["name"]], ["relation", "twin", ["a", "b"]], ["relation", "mother", ["child", "mother"], {"key": "child"}], ["fact", ["person", "ben"], ["person", "cy"], ["person", "dee"]], ["fact", ["twin", "ben", "cy"]], ["rule", ["exists", ["?m"], ["mother", "?c", "?m"]], ["person", "?c"]], ["rule", ["mother", "?b", "?m"], ["twin", "?a", "?b"], ["mother", "?a", "?m"]], ["rule", ["mother", "?a", "?m"], ["twin", "?a", "?b"], ["mother", "?b", "?m"]], {"mothers": ["query", ["mother", "?child", "?mother"], {"order": "child"}], "why cy": ["why", ["mother", "cy", ["some", "?m", ["mother", "ben", "?m"]]]]}]

Two different values that nobody invented, such as two given mothers, are still an error. An unknown that a fact holds is given, not invented, so a key never changes it.

A key can also make an invented unknown equal to a value that was given. Here every person's mother is a woman, and the key says ada's one mother is fay, so the unknown woman the rule invents for ada is fay, and fay is a woman. why explains such a row by the rule that invented it, with a same premise that says what the key made its unknown equal to:

["begin", ["relation", "person", ["name"]], ["relation", "woman", ["name"]], ["relation", "mother", ["child", "mother"], {"key": "child"}], ["fact", ["person", "ada"], ["mother", "ada", "fay"]], ["rule", ["exists", ["?m"], ["and", ["mother", "?c", "?m"], ["woman", "?m"]]], ["person", "?c"]], {"mothers": ["find", ["array/make", "?c", "?m"], ["mother", "?c", "?m"]], "women": ["find", "?w", ["woman", "?w"]], "why fay": ["why", ["woman", "fay"]]}]

Say that two values are the same

A rule's head can be ["=", a, b]: an equality rule. Whenever its body holds, the two sides are one value. While the relations its body reads are derived, an unknown that a rule invented takes the value on the other side, as it does under a key. Here twins share a mother, and a registered mother is the one a person has:

["begin", ["relation", "person", ["name"]], ["relation", "twin", ["a", "b"]], ["relation", "mother", ["child", "mother"]], ["relation", "registered", ["child", "mother"]], ["fact", ["person", "ben"], ["person", "cy"], ["person", "dee"], ["twin", "ben", "cy"]], ["fact", ["registered", "dee", "eve"]], ["rule", ["exists", ["?m"], ["mother", "?c", "?m"]], ["person", "?c"]], ["rule", ["=", "?m1", "?m2"], ["twin", "?a", "?b"], ["mother", "?a", "?m1"], ["mother", "?b", "?m2"]], ["rule", ["=", "?m", "?r"], ["mother", "?c", "?m"], ["registered", "?c", "?r"]], {"mothers": ["query", ["mother", "?child", "?mother"], {"order": "child"}], "why cy": ["why", ["mother", "cy", ["some", "?m", ["mother", "ben", "?m"]]]]}]

An equality rule also holds as the invariant it stands for, ["and", goal, ..., ["not", ["=", a, b]]]. A rule that does not hold is not added, and a change that leaves two different known values under it is refused, in an invariant's words. A body that reads only facts has no unknowns to make one, so there the rule is only that check:

["begin", ["relation", "email", ["person", "address"]], ["rule", ["=", "?a", "?b"], ["email", "?p", "?a"], ["email", "?p", "?b"]], ["fact", ["email", "ann", "a@x"]], ["fact", ["email", "ann", "ann@y"]]]

An equality rule runs with a relation its body reads that rules derive, one no other of them depends on, and one whose rules invent when there is one, so every other relation it reads is complete first. It cannot change an unknown invented for a relation below that one; the invariant reports such a pair.

State that something exists in a fact

A fact can hold exists too. It adds the row with an unknown in it, the very row a rule with that head would invent. A fact states rows, so it adds the row whether or not the head holds already. why and retract take exists the same way:

["begin", ["relation", "mother", ["child", "mother"]], ["fact", ["exists", ["?m"], ["mother", "ben", "?m"]]], {"rows": ["query", ["mother", "?child", "?mother"]], "why": ["why", ["exists", ["?m"], ["mother", "ben", "?m"]]]}]

A snapshot writes an unknown as its some form, and a rule that invents with its exists head, so a saved database keeps both. See Save and load a logic database.

Keep inventions finite

Rules that invent can recurse, as long as what they invent never flows back into inventing more. "Every person has a mother" with "every mother is a person" would invent mothers without end, so Lion refuses the rule that closes the loop. The message names the rule that would invent:

["begin", ["relation", "person", ["name"]], ["relation", "mother", ["child", "mother"]], ["rule", ["exists", ["?m"], ["mother", "?p", "?m"]], ["person", "?p"]], ["rule", ["person", "?m"], ["mother", "?p", "?m"]]]

Invent the value in a rule that does not recurse. A rule that invents also cannot aggregate. See Termination for the rule.
