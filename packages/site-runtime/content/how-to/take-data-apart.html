This guide shows how to get at the parts of nested data in a rule or query. A schema with a logic variable in it is a pattern: the variable takes the value it meets, so one goal checks a value and takes it apart.

Bind the fields of a record

Write the record you are looking for as an argument of a relation call, with a variable where a value should go. The call asks for the rows that fit, and binds the variables:

["begin", ["relation", "inbox", ["doc"]], ["fact", ["inbox", {"type": "refund", "id": 3}], ["inbox", {"type": "refund", "id": 4}], ["inbox", {"type": "order", "id": 1}]], ["query", ["inbox", {"type": "refund", "id": "?id"}], {"order": "id"}]]

A record in a pattern fits a record with the same keys. The value "refund" fits only itself, so it picks the rows, and ?id takes the id of each.

Take some keys of a larger record

schema/open fits a record whatever other keys it has, so a pattern can name only the keys it needs. ?_ fits any value and binds nothing, which asks only that a key is there:

["begin", ["relation", "inbox", ["doc"]], ["fact", ["inbox", {"type": "order", "id": 1, "note": "gift"}], ["inbox", {"type": "order", "id": 2, "rush": true}], ["inbox", {"type": "refund", "id": 3}]], {"orders": ["find", "?id", ["inbox", ["schema/open", {"type": "order", "id": "?id"}]]], "with a note": ["find", "?id", ["inbox", ["schema/open", {"id": "?id", "note": "?_"}]]]}]

Go through a list inside a record

The element of in can be a pattern too. Here one goal takes the lines out of each order, and in takes each line apart, so a rule turns nested documents into rows that other rules can count:

["begin", ["relation", "inbox", ["doc"]], ["relation", "line", ["order", "sku", "qty"]], ["relation", "units", ["order", "total"]], ["fact", ["inbox", ["quote", {"id": 1, "lines": [{"sku": "a1", "qty": 2}, {"sku": "b2", "qty": 1}]}]], ["inbox", ["quote", {"id": 2, "lines": [{"sku": "a1", "qty": 5}]}]]], ["rule", ["line", "?order", "?sku", "?qty"], ["inbox", {"id": "?order", "lines": "?lines"}], ["in", {"sku": "?sku", "qty": "?qty"}, "?lines"]], ["rule", ["units", "?order", ["aggregate/sum", "?qty"]], ["line", "?order", "?sku", "?qty"]], {"lines": ["find", ["array/make", "?order", "?sku", "?qty"], ["line", "?order", "?sku", "?qty"]], "units": ["query", ["units", "?order", "?total"], {"order": "order"}]}]

Take a list apart by position

A list of variables fits a list of the same length. = matches one side against the other, so it binds the variables on either side:

["begin", ["relation", "route", ["stops"]], ["fact", ["route", ["array/make", "oslo", "bergen", "voss"]], ["route", ["array/make", "rome", "pisa", "turin"]], ["route", ["array/make", "kyoto", "nara"]]], ["query", ["and", ["route", "?stops"], ["=", ["array/make", "?from", "?_", "?to"], "?stops"]], {"order": "from"}]]

The route with two stops has no answer, since the pattern has three places.

Check a part while you take it

Every schema works in a pattern. A predicate says what a part must be, schema/allOf checks a part and binds it, and schema/anyOf offers a choice. A predicate can be made from a variable that another goal binds:

["begin", ["relation", "reading", ["sensor", "celsius"]], ["relation", "limit", ["celsius"]], ["fact", ["reading", "attic", 30], ["reading", "cellar", 10], ["reading", "roof", "n/a"], ["limit", 25]], {"numbers": ["find", "?sensor", ["reading", "?sensor", "value/number?"]], "hot": ["find", "?sensor", ["and", ["limit", "?max"], ["reading", "?sensor", ["func/partial", "number/lessThan", "?max"]]]], "attic or roof": ["query", ["reading", ["schema/anyOf", "attic", "roof"], "?celsius"]], "checked": ["query", ["reading", "?sensor", ["schema/allOf", "value/number?", "?celsius"]], {"order": "sensor"}]}]

Take apart a value you already have

schema/fits? is the same goal for a value that another goal bound, or one from outside. With a named schema and a pattern in one schema/allOf, a rule keeps the documents that fit and takes them apart at once:

["begin", ["relation", "inbox", ["doc"]], ["relation", "order", ["id", "status"], {"key": "id"}], ["schema", "Order", {"id": "value/integer?", "status": ["schema/anyOf", "open", "shipped"]}], ["fact", ["inbox", {"id": 1, "status": "open"}], ["inbox", {"id": 2, "status": "opne"}], ["inbox", {"id": "3", "status": "shipped"}]], ["rule", ["order", "?id", "?status"], ["inbox", ["schema/allOf", "Order", {"id": "?id", "status": "?status"}]]], {"orders": ["query", ["order", "?id", "?status"]], "one value": ["query", ["schema/fits?", ["quote", {"id": 7, "status": "open"}], {"id": "?id", "status": "?status"}]]}]

The order of the goals in a rule does not matter: a goal that binds through a pattern gives what it gives when another goal has bound its variables first.
