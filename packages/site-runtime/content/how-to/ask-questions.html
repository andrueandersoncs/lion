This guide shows how to use what the database knows inside ordinary expressions, in plain code and inside rules.

Collect answers into a list

find takes a template and a goal, and returns the template's value for every match of the goal, sorted:

["begin", ["relation", "score", ["player", "points"]], ["fact", ["score", "ana", 12], ["score", "bo", 30], ["score", "cy", 30]], {"players": ["find", "?player", ["score", "?player", "?_"]], "by points": ["find", ["array/make", "?points", "?player"], ["score", "?player", "?points"]], "best": ["aggregate/max", ["find", "?points", ["score", "?_", "?points"]]]}]

The result is a plain list, so every list function works on it. Where query returns one record per answer for you to read, find returns exactly the values you ask for.

Test a goal

A goal is true when it has a match and false when it has none. Use it wherever a value is needed, such as a cond condition or a value of a record:

["begin", ["relation", "member", ["name", "plan"]], ["relation", "blocked", ["name"]], ["fact", ["member", "ana", "pro"], ["member", "bo", "free"]], ["fact", ["blocked", "bo"]], ["define", "access", ["lambda", ["who"], ["cond", [["blocked", "who"], "none"], [["member", "who", "pro"], "full"], [["member", "who", "?_"], "limited"], ["else", "guest"]]]], {"ana": ["access", "ana"], "bo": ["access", "bo"], "zed": ["access", "zed"], "anyone blocked": ["blocked", "?_"]}]

A goal with a variable asks whether anything matches. Give a variable a name when the goal joins on it, as in ["and", ["member", "?m", "pro"], ["blocked", "?m"]].

Use a relation as a predicate

A relation is a function that builds a goal, so it works as the predicate of match and of functions that take one:

["begin", ["relation", "vowel", ["letter"]], ["fact", ["vowel", "a"], ["vowel", "e"], ["vowel", "i"], ["vowel", "o"], ["vowel", "u"]], {"flags": ["array/map", ["array/make", "l", "i", "o", "n"], "vowel"], "kind": ["match", "o", ["vowel", ["lambda", ["letter"], "a vowel"]], ["lambda", ["letter"], "a consonant"]]}]

Ask from inside a rule

In a rule or query the same expressions are asked once for each answer, with the answer's variables in place. A variable that only the question mentions, such as ?child here, belongs to the question:

["begin", ["relation", "person", ["name"]], ["relation", "parent", ["parent", "child"]], ["relation", "profile", ["name", "summary"]], ["fact", ["person", "ada"], ["person", "ben"], ["person", "cy"]], ["fact", ["parent", "ada", "ben"], ["parent", "ada", "cy"]], ["rule", ["profile", "?p", {"children": ["find", "?child", ["parent", "?p", "?child"]], "kind": ["cond", [["parent", "?p", "?_"], "has children"], ["else", "no children"]]}], ["person", "?p"]], ["query", ["profile", "?name", "?summary"], {"order": "name"}]]

A lambda that asks works in both places, because its body is asked wherever it runs:

["begin", ["relation", "person", ["name"]], ["relation", "parent", ["parent", "child"]], ["fact", ["person", "ada"], ["person", "ben"]], ["fact", ["parent", "ada", "ben"], ["parent", "ada", "cy"]], ["define", "children", ["lambda", ["p"], ["find", "?c", ["parent", "p", "?c"]]]], {"in plain code": ["children", "ada"], "in a query": ["query", ["and", ["person", "?p"], ["=", "?kids", ["children", "?p"]]], {"order": "p"}]}]

Keep a goal as a goal

define, and, or, not, and lambdas do not ask a goal: they keep it, so you can name goals and build bigger ones. Here the program's result is the goal itself:

["begin", ["relation", "member", ["name", "plan"]], ["define", "is-pro", ["member", "?who", "pro"]], ["and", "is-pro", ["not", ["member", "?who", "free"]]]]

A goal is asked only where a value is needed. A record holds values, so it asks. To get a goal's truth on its own, give the goal to value/identity:

["begin", ["relation", "member", ["name", "plan"]], ["fact", ["member", "ana", "pro"]], ["define", "is-pro", ["member", "?who", "pro"]], {"in a record": "is-pro", "its truth": ["value/identity", "is-pro"], "its answers": ["query", "is-pro"]}]
