This guide shows how to run classic graph algorithms over an edge relation with the graph module. Each algorithm is called like a relation, so its rows work in queries, rules, not, and aggregates.

Find shortest routes

Give graph/shortestPath an edge relation and a start node, then one term each for the destination, the cost, and the path. A third edge column is the weight:

["begin", ["relation", "road", ["from", "to", "km"]], ["fact", ["road", "a", "b", 4], ["road", "a", "c", 1], ["road", "c", "b", 2], ["road", "b", "d", 5]], ["query", ["graph/shortestPath", "road", "a", "?to", "?km", "?path"]]]

To ask about one destination, give it as a value: ["graph/shortestPath", "road", "a", "d", "?km", "?_"]. Without a weight column, every edge costs 1.

Rank nodes

["begin", ["relation", "link", ["from", "to"]], ["fact", ["link", "a", "b"], ["link", "b", "c"], ["link", "c", "a"], ["link", "d", "c"]], ["query", ["graph/pageRank", "link", "?page", "?rank"], {"order": "-rank"}]]

Group connected nodes

graph/components ignores edge direction; graph/stronglyConnected follows it. Groups are named after their smallest node:

["begin", ["relation", "edge", ["from", "to"]], ["fact", ["edge", "a", "b"], ["edge", "b", "a"], ["edge", "b", "c"], ["edge", "x", "y"]], {"connected": ["query", ["graph/components", "edge", "?node", "?group"], {"order": "node"}], "strong": ["query", ["graph/stronglyConnected", "edge", "?node", "?group"], {"order": "node"}]}]

Order dependencies

graph/topologicalOrder numbers nodes so every edge points forward, or fails with an error that names a cycle:

["begin", ["relation", "before", ["first", "then"]], ["fact", ["before", "socks", "shoes"], ["before", "pants", "shoes"], ["before", "shirt", "tie"]], ["query", ["graph/topologicalOrder", "before", "?step", "?position"], {"order": "position"}]]

Use results in rules

Algorithm rows can feed rules. Here, nodes far from the start are flagged:

["begin", ["relation", "road", ["from", "to", "km"]], ["relation", "remote", ["place"]], ["fact", ["road", "a", "b", 4], ["road", "a", "c", 1], ["road", "c", "b", 2], ["road", "b", "d", 5]], ["rule", ["remote", "?p"], ["graph/shortestPath", "road", "a", "?p", "?km", "?_"], ["number/greaterThan", "?km", 5]], ["query", ["remote", "?place"]]]

An algorithm runs once its input relation is complete, so it cannot be part of a recursive cycle, and its relation cannot have facts or rules of its own.
