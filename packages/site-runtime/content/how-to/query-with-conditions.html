This guide shows how to go beyond matching facts: filter answers with conditions, compute values, accept alternatives, and match items of a list.

Filter answers with a condition

Call a function from a pure module (number, string, boolean, array, value) on a logic variable, and it becomes a filter. Combine goals with and:

["begin", ["relation", "order", ["id", "amount"]], ["fact", ["order", 1, 30], ["order", 2, 120], ["order", 3, 75]], ["query", ["and", ["order", "?id", "?amount"], ["number/greaterThan", "?amount", 50]], {"order": "id"}]]

A filter runs once its variables are bound, so its position among the goals does not matter.

Compute a value

Use = to bind a variable to a computed value:

["begin", ["relation", "order", ["id", "amount"]], ["fact", ["order", 1, 30], ["order", 2, 120]], ["query", ["and", ["order", "?id", "?amount"], ["=", "?withTax", ["number/multiply", "?amount", 1.25]]], {"order": "id"}]]

In a rule, a computed value can also go straight into the head:

["begin", ["relation", "user", ["id", "first", "last"]], ["relation", "fullName", ["id", "name"]], ["fact", ["user", 1, "Ada", "Lovelace"], ["user", 2, "Alan", "Turing"]], ["rule", ["fullName", "?id", ["string/concat", ["string/concat", "?first", " "], "?last"]], ["user", "?id", "?first", "?last"]], ["query", ["fullName", "?id", "?name"], {"order": "id"}]]

Accept alternatives

or holds when any of its goals does:

["begin", ["relation", "order", ["id", "status"]], ["fact", ["order", 1, "open"], ["order", 2, "paid"], ["order", 3, "held"]], ["query", ["or", ["order", "?id", "open"], ["order", "?id", "held"]], {"order": "id"}]]

Match items of a list

When a fact holds a list, in binds a variable to each item:

["begin", ["relation", "post", ["id", "tags"]], ["fact", ["post", "p1", ["array/make", "lisp", "json"]], ["post", "p2", ["array/make", "json", "logic"]]], ["query", ["and", ["post", "?post", "?tags"], ["in", "json", "?tags"]], {"order": "post"}]]

With an unbound first argument, in binds it to each item; with a bound one, it tests membership, as above.

Keep goals safe

Every variable in a filter, a computed value, or a not must be bound by a relation, =, or in somewhere in the same goal. Otherwise there would be infinitely many answers, so Lion refuses the goal and names the variable:

["query", ["number/greaterThan", "?amount", 50]]
