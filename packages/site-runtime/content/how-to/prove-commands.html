This guide shows how to prove that a model keeps a rule: not for the runs a search tried, but for every state the rule allows and every command, which is the step of a proof by induction. A schema types the state and the command, and the solver works out every value they can take.

Prove that a command keeps a rule

An account has a balance and an overdraft limit, and a withdrawal that would go past the limit is refused. A rule is kept when no state the rule allows, and no command, leads to a state that breaks it. Ask whether such a state exists, under not: [{}] is the proof, for every account and every command, and [] says some state and command break the rule:

Notice a proof that holds of no state

A proof that a rule is kept asks whether any state the rule allows, and any command, break it. When the rule allows no state at all, no state breaks it, and the proof holds of nothing. Write the proof as a rule, and why says which goals contradict each other, and "vacuous": true when they leave out the goal the proof denies:

Prove properties by induction

For universal questions (["not", ["exists", ...]]) over recursive named schemas, unbounded lists (schema/arrayOf), or lower-bounded integers, the solver proves by structural or numeric induction whenever the recursive functions involved are pure, strictly decrease on a structural sub-part or lower-bounded integer measure, and return a uniform sort. Products of unknowns are tracked as exact polynomials so matching nonlinear terms cancel in induction steps:

Prove properties of rules by rule induction

Ask whether one schema includes another

schema/includes? says whether every value one schema allows fits another, exactly: by listing the first schema's values when it can list them, and by the solver otherwise — across value kinds, open records and lists, unbounded collections, and recursive or mutually recursive named schemas (including uninhabited recursive schemas). It refuses, and says why, only when neither can decide an arbitrary predicate:
