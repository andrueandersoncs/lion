This guide shows how to prove that a model keeps a rule: not for the runs a search tried, but for every state the rule allows and every command, which is the step of a proof by induction. A schema types the state and the command, and the solver works out every value they can take.

Prove that a command keeps a rule

An account has a balance and an overdraft limit, and a withdrawal that would go past the limit is refused. A rule is kept when no state the rule allows, and no command, leads to a state that breaks it. Ask whether such a state exists, under not: [{}] is the proof, for every account and every command, and [] says some state and command break the rule:

Check a proof yourself

Where a step of the solver stopped a rule, why shows a certificate for each case the solver split the goals into: the constraints, as whole-number sums compared with 0, and steps that each add earlier lines, each multiplied by a whole number, and over whole numbers may tighten the sum, dividing it by the greatest common divisor of its coefficients and rounding its constant down. The last line has no variables and is false, so the constraints have no solution. Checking it takes only arithmetic, so a small program can, without trusting the solver. Ask whether one schema includes another

schema/includes? says whether every value one schema allows fits another, exactly: by listing the first schema's values when it can list them, and by the solver otherwise. It refuses, and says why, what neither can decide, such as whether every number is a whole number, or anything about every string:
