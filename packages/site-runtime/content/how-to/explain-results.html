This guide shows how to use why to trace a derived fact back to its sources.

Ask why a fact holds

Give why the fact, with no variables:

["begin", ["relation", "edge", ["from", "to"]], ["relation", "path", ["from", "to"]], ["fact", ["edge", "a", "b"], ["edge", "b", "c"]], ["rule", ["path", "?x", "?y"], ["edge", "?x", "?y"]], ["rule", ["path", "?x", "?z"], ["path", "?x", "?y"], ["edge", "?y", "?z"]], ["why", ["path", "a", "c"]]]

Each level names the fact, the rule that derived it, and the facts because of which it holds. A fact you added says "given": true.

Read filters and negations

Filters appear as check, with the values they were called on, and negations as absent, with the pattern that had no match:

["begin", ["relation", "user", ["name", "age"]], ["relation", "banned", ["name"]], ["relation", "eligible", ["name"]], ["fact", ["user", "ana", 34]], ["rule", ["eligible", "?n"], ["user", "?n", "?age"], ["number/greaterThan", "?age", 18], ["not", ["banned", "?n"]]], ["why", ["eligible", "ana"]]]

See how a figure was worked out

A rule that computes a value with = shows the computation as a check too, with the values it was given in place of its variables, so a ratio or a total traces to the rows it came from. Every check, evaluated as it stands, is true, so anyone can work the arithmetic again:

["begin", ["relation", "line", ["item", "usd_m"]], ["relation", "gross_margin", ["percent"]], ["fact", ["line", "revenue", 409.8], ["line", "cost of services", 301.5]], ["rule", ["gross_margin", "?percent"], ["line", "revenue", "?revenue"], ["line", "cost of services", "?cost"], ["=", "?percent", ["number/divide", ["number/round", ["number/multiply", 1000, ["number/divide", ["number/subtract", "?revenue", "?cost"], "?revenue"]]], 10]]], ["why", ["gross_margin", ["array/head", ["find", "?p", ["gross_margin", "?p"]]]]]]

The figure in the last line is itself worked out, with find, so the program never states the 26.4 it explains.

See what a pattern matched

A goal can say which rows it wants with a pattern or a schema, and then the goal itself does not say which row it found. why does: the premise is the row the goal matched. A schema check that held is a check:

["begin", ["relation", "inbox", ["doc"]], ["relation", "big", ["id"]], ["schema", "Order", ["schema/open", {"id": "value/integer?"}]], ["fact", ["inbox", {"id": 1, "total": 80, "note": "gift"}], ["inbox", {"id": 2, "total": 20}]], ["rule", ["big", "?id"], ["inbox", ["schema/open", {"id": "?id", "total": "?total"}]], ["schema/fits?", {"id": "?id"}, "Order"], ["number/greaterThan", "?total", 50]], ["why", ["big", 1]]]

See what an aggregate combined

For an aggregated fact, why lists every match it combined under matches. For min, max, and shortest, it explains the one match that produced the value.

["begin", ["relation", "order", ["id", "customer", "amount"]], ["relation", "spend", ["customer", "total"]], ["fact", ["order", 1, "ana", 30], ["order", 2, "ana", 20]], ["rule", ["spend", "?c", ["aggregate/sum", "?a"]], ["order", "?_", "?c", "?a"]], ["why", ["spend", "ana", 50]]]

Handle facts that do not hold

why returns null when the fact does not hold, so you can test the result:

["begin", ["relation", "edge", ["from", "to"]], ["fact", ["edge", "a", "b"]], ["why", ["edge", "b", "a"]]]
