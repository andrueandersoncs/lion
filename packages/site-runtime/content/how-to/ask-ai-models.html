This guide shows how to call TypeSafe's System One models from Lion with @lionlang/typesafe-ai. You need a TypeSafe API key. These examples call a paid API, so they are not live on this page.

Add the bindings

bun add @lionlang/typesafe-ai export TYPESAFE_API_KEY=... import { Effect } from "effect"; import { run } from "@lionlang/core/evaluation/evaluate"; import { stdlib } from "@lionlang/core/modules"; import { makeTypeSafeBindings } from "@lionlang/typesafe-ai"; const env = { ...stdlib, ...makeTypeSafeBindings() };

makeTypeSafeBindings takes the TypeSafe client configuration and an optional namespace, "typesafe" by default.

Ask several questions about one input

typesafe/system-one takes the state to judge and a record of questions. Build each question with typesafe/noul (yes or no), typesafe/choice (one of several labels), or typesafe/score (a point on a scale):

["typesafe/system-one", { "state": "Help! My payouts have been failing for 3 days.", "questions": { "urgent": ["typesafe/noul", "Does this convey urgency?", {"true": "Explicitly time-sensitive", "false": "No urgency expressed"}], "team": ["typesafe/choice", "Which team should handle this?", {"billing": "Payments and refunds", "technical": "Bugs and outages"}], "frustration": ["typesafe/score", "How frustrated is the customer?", ["quote", ["Calm", "Frustrated", "Very angry"]]]}}]

Lists in the request are data, so they are quoted. Each answer comes back with its probabilities, so a program can branch on confidence with cond.

Try it in the editor

In the graph editor (lion repl), the Jev button loads a starter System One program. The editor asks for a key on the first run and keeps it only in the tab's memory.
