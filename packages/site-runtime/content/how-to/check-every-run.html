This guide shows how to check a model of commands: a step function that takes a state and a command to the next state. Lion asks about every run of commands up to a length, which a schema like ["schema/arrayOf", "Command", 3] stands for, and about every state a run passes through. When a command carries an amount that a schema types, such as any positive whole number, the solver works the amounts out, so the check covers every amount, not only the ones a test tried.

Follow the states a run passes through

array/reductions gives every value array/reduce passes through, starting with the first, so for a step function it gives the states a run goes through:

["array/reductions", ["quote", [{"deposit": 5}, {"withdraw": 3}, {"withdraw": 4}]], 0, ["lambda", ["balance", "c"], ["cond", [["value/number?", ["object/get", "c", "deposit"]], ["number/add", "balance", ["object/get", "c", "deposit"]]], ["else", ["number/subtract", "balance", ["object/get", "c", "withdraw"]]]]]]

Check that a rule always holds

A rule always holds when no state of any run breaks it. Type the run with a schema, take each state with in, and ask whether one breaks the rule. Here the amounts are any positive whole numbers. A careful withdrawal, which refuses to take more than the balance, never takes the account below 0, while a careless one can:

["begin", ["schema", "Amount", ["schema/allOf", "value/integer?", ["lambda", ["n"], ["number/greaterThan", "n", 0]]]], ["schema", "Command", ["schema/anyOf", {"deposit": "Amount"}, {"withdraw": "Amount"}]], ["define", "careful", ["lambda", ["balance", "c"], ["cond", [["value/number?", ["object/get", "c", "deposit"]], ["number/add", "balance", ["object/get", "c", "deposit"]]], [["number/lessThan", "balance", ["object/get", "c", "withdraw"]], "balance"], ["else", ["number/subtract", "balance", ["object/get", "c", "withdraw"]]]]]], ["define", "careless", ["lambda", ["balance", "c"], ["cond", [["value/number?", ["object/get", "c", "deposit"]], ["number/add", "balance", ["object/get", "c", "deposit"]]], ["else", ["number/subtract", "balance", ["object/get", "c", "withdraw"]]]]]], ["define", "overdraws", ["lambda", ["step"], ["query", ["exists", ["?run", "?balance"], ["and", ["schema/fits?", "?run", ["schema/arrayOf", "Command", 3]], ["in", "?balance", ["array/reductions", "?run", 0, "step"]], ["number/lessThan", "?balance", 0]]]]]], {"careful": ["overdraws", "careful"], "careless": ["overdraws", "careless"]}]

[] means no run of up to three commands, with any amounts, breaks the rule; [{}] means some run does.

Find the shortest run that breaks a rule

A rule with the run's length in its head, and the run only in its body, gives each length of a run that breaks the rule, however many runs of that length do. why shows a run of that length with amounts that break it:

Check that something eventually happens

Something must eventually happen when some state of every run meets it: array/some? over the states. Which runs have run their course is a goal about the run, such as its length. Here a heater starts at 0 and each command heats it by an amount between two bounds. In three steps it always reaches 20 degrees when each step heats by 7 to 10, and not when a step may heat by only 5:

["begin", ["define", "heater", ["lambda", ["low", "high"], {"heat": ["schema/allOf", "value/integer?", ["lambda", ["n"], ["boolean/and", ["number/greaterThanOrEqualTo", "n", "low"], ["number/lessThanOrEqualTo", "n", "high"]]]]}]], ["define", "always warm", ["lambda", ["command"], ["query", ["not", ["exists", ["?run"], ["and", ["schema/fits?", "?run", ["schema/arrayOf", "command", 3]], ["number/equals?", ["array/length", "?run"], 3], ["not", ["array/some?", ["array/reductions", "?run", 0, ["lambda", ["t", "c"], ["number/add", "t", ["object/get", "c", "heat"]]]], ["lambda", ["t"], ["number/greaterThanOrEqualTo", "t", 20]]]]]]]]]], {"heating by 5 to 10": ["always warm", ["heater", 5, 10]], "heating by 7 to 10": ["always warm", ["heater", 7, 10]]}]

The schema here is made by a function the check is given, and is solved for as one written under a name is.

Know what it decides

A run's length is known in each shape the schema gives it, so the solver runs the step function on each command in turn, on amounts it works out, and decides what it decides everywhere: sums of numbers times known numbers, comparisons, and equality. A step it cannot decide, such as one that multiplies two amounts, waits for listed values, and so needs the amounts bounded.
