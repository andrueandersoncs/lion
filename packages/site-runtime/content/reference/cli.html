Install with bun add --dev @lionlang/cli. The package provides the lion command.

lion [<file>...]

lion [--database <path>] [--read-only] [--bind <name=json>]... [--bind-file <name=path>]... [--eval <json>] [<file>...]

Reads one or more Lion programs as JSON from files (evaluated sequentially against one database, each with a fresh top-level environment), --eval (-e), or standard input (when file is - or omitted while stdin is piped), evaluates them with the standard library and any --bind / --bind-file bindings, and prints the final result as JSON indented by two spaces.

Argument or flagMeaning
file...One or more paths to Lion programs in JSON (run in order against one database), or - to read from standard input. Optional when --eval is passed or stdin is piped.
--eval <json>, -e <json>Evaluate a Lion program written directly on the command line instead of reading files.
--bind <name=json>, -b <name=json>Bind a top-level name to a JSON value, preserving exact decimals and large integers. Repeatable; overrides --bind-file for the same name.
--bind-file <name=path>Bind a top-level name to the JSON value read from a file, preserving exact numbers. Repeatable.
--database <path>A JSON file that holds the logic database. It is loaded before the programs run; if it does not exist, the database starts empty. After all programs succeed, the database is saved back as a snapshot (one form and one fact per line) only if the file did not exist or the database changed. If any program fails, the file is not written.
--read-only, -rLoad --database without ever writing changes back to disk, even if the program asserts or retracts facts or rules.

lion inspect [<file>]

lion inspect [--derived] (<file> | --database <path>)

Loads a saved database read-only and prints a concise JSON summary of its ontology: every relation (columns, key, merge, base fact count, rule count, and optionally total derived row count with --derived), every named schema and its shape, every invariant, and summary totals.

Argument or flagMeaning
file / --database <path>Path to the saved Lion database file to inspect. Never modified.
--derived, -dAlso evaluate rules and include total row counts (rows) for each relation.

lion check [<file>]

lion check [--database <path>] [--bind <name=json>]... [--bind-file <name=path>]... [--eval <json>] [<file>]

Reads a program without running it and prints a JSON list of diagnostics and warnings, each with its JSON pointer in at: malformed forms, misspelled namespaced names, wrong-arity calls to known functions, relations, schemas, or lambdas, invalid relation/query/invariant options, unsafe rule heads or find templates, logic variables in ground facts, unreachable or non-exhaustive match cases, unreachable cond branches after else, duplicate lambda parameters, near-miss bare call heads, and Lion lints such as lists written as bare arrays inside rules or queries. Exits with status 1 when any error is found.

Argument or flagMeaning
filePath to a Lion program in JSON, or - to read from standard input. Optional when --eval is passed or stdin is piped.
--eval <json>, -e <json>Check a Lion program written directly on the command line.
--bind <name=json>, -b <name=json>Declare a top-level binding while checking the program. Repeatable.
--bind-file <name=path>Declare a top-level binding from a JSON file while checking the program. Repeatable.
--database <path>Load a saved database read-only before checking, so calls to its declared relations and schemas are recognized and checked for arity without modifying the file.

lion repl

lion repl [--host <address>] [--port <number>]

Serves the Fold Map graph editor bundled with the command, and prints its address. It runs until stopped.

FlagDefaultMeaning
--host127.0.0.1Address to listen on.
--port3000Port to listen on, from 1 to 65535.

lion worker

lion worker > lion-worker.js

Prints the command's own Lion as a Web Worker script, for a page that runs Lion in a browser. The worker holds one logic database. Each message posted to it has an id, and each answer it posts back has the same id, ok, the value as JSON text in json or the reason in error, and ms, how long it took.

MessageMeaning
{"type": "load", "snapshot": saved}Loads a database from a saved one, as --database loads its file, in place of the one the worker held.
{"type": "run", "program": program}Runs a program against the database, as lion <file> --database does. A program can change the database.

These are the answers the worker gives to a database of edges and the paths they make, and two programs run against it, without ms:

{"id":1,"type":"load","snapshot":["begin", ["relation","edge",["from","to"]],["relation","path",["from","to"]], ["fact",["edge","a","b"],["edge","b","c"]], ["rule",["path","?x","?y"],["edge","?x","?y"]], ["rule",["path","?x","?z"],["path","?x","?y"],["edge","?y","?z"]]]} answers {"id":1,"ok":true,"json":"null"} {"id":2,"type":"run","program":["find","?to",["path","a","?to"]]} answers {"id":2,"ok":true,"json":"[\"b\",\"c\"]"} {"id":3,"type":"run","program":["path","a"]} answers {"id":3,"ok":false,"error":"\"path\" takes 2 arguments (from, to) but got 1."}

A page that carries the script runs the Lion of the command that printed it, so running the page's programs with that command checks the page.

Global flags

FlagMeaning
--help, -hShow help for the command or subcommand.
--version, -vShow the version.
--wizardBuild the command interactively.
--completions <shell>Print a completion script for bash, zsh, fish, powershell, sh, or pwsh.
--log-level <level>Minimum log level: all, trace, debug, info, warn, error, fatal, or none.

Exit status

0 when the program succeeds. 1 when the file cannot be read or parsed, the program fails, or the database cannot be loaded or saved; the error is printed.
