A failed evaluation is a typed Effect failure. Each error has a _tag you can catch with Effect.catchTag. On this page and in the editor, failures show as Tag: message.

TagRaised when
SchemaErrorThe program is not a valid Lion expression, such as a record key __proto__, or eval is given something that is not JSON.
UnboundNameErrorA string of the form module/name is evaluated, nothing is bound to it, and it reads as a misspelled name: other names of its module are bound, or a bound name is a letter or two away, which the message suggests. The error holds the string as unbound and the suggestion, or null, as nearest. Inside quote the string is data.
InvalidFunctionCallErrorAn array's first element does not evaluate to a function, including a string no scope declares. A misspelled module/name is an UnboundNameError instead.
MalformedFormErrorAn array starts with a special form's name that no scope declares, but does not have the form's shape, such as ["define", "x"]. The message says what the form takes, with an example. The error holds the array as expression, the form's name as form, and what it takes as usage.
UndefinedYetErrorA name is read before the define, relation, or schema form that binds it has run. A body declares the names it defines from its start, so the string means that definition, which has no value yet. A body that defines the name of a form it uses, as ["define", "define", 1] does, fails with it too, and the message says so. The error holds the name as unassigned.
ArithmeticErrorArithmetic has no result, as division by zero has none, or a whole power would have more than 4,300 digits. Numbers are exact, so no sum or product overflows. A value is written as JSON text with a fraction no decimal writes, such as 1/3, which JSON cannot hold.
LogicErrorA logic form fails: an unsafe goal or rule, a recursion or question that breaks the rules, a broken invariant or query assertion, a key conflict, a bad option, and more. The message says what and where. A function called with the wrong number of arguments, or with an argument it does not take, fails with one too, as "number/add" takes a number as argument 1 but got "one".
WaitingErrorA value was needed before it is known. A host function gets this error from call when a Lion function's value is not known yet; the call the host function is part of then waits, so a program does not see it. A program sees it when a fact, retract, or why written inside a rule, query, or find is given a question: those forms act right away, so they cannot wait.
NotAnObjectErrorA function that reads keys received something that is not an object, or a method function received null.
KeyNotFoundErrorobject/get-path reached a key that is not there.
IndexOutOfBoundsErrorobject/get-path indexed past the end of a list.
NotAnArrayErrorobject/get-path used a numeric segment on something that is not a list.
PathTraversalErrorA path passed through a value that is not an object before its last key, or a key that is not there.
InvalidPathErrorA path argument is not a string.
NotAFunctionErrorobject/call-method or object/get-method named something that is not a method.
MethodNotFoundErrorThe end of a method path is not a method.
EmptyPathErrorA method path is empty.
NotAConstructorErrorobject/new was given something that is not a class.

Examples

The functions a failure left

A failure that leaves the body of a function says so: its message ends with the functions it left, innermost first. A function has a name there when a define bound it, as in Racket. A function that made its call in tail position has nothing left of its own when the failure passes, as in Scheme, so it is not named; neither is a function no define bound. The failure keeps its kind.

["begin", ["define", "next", ["lambda", ["n"], ["number/add", "n", 1]]], ["define", "label", ["lambda", ["n"], ["string/concat", "item ", ["next", "n"]]]], ["label", "seven"]]

Errors inside rules and queries

A function that fails while a rule or query runs it fails the rule or query. A function given a value it does not take says which function, which argument, and what it got, as it does in plain code. Any other failure is a LogicError that names the call and the values it ran on. An ArithmeticError stays as it is, since it already names both. A filter that is not true or false, and an answer that is not data, fail with a LogicError too.

["begin", ["relation", "reading", ["value"]], ["fact", ["reading", 4], ["reading", "n/a"]], ["query", ["and", ["reading", "?v"], ["number/greaterThan", "?v", 3]]]]

Errors from host functions

A host function that returns a failed Effect fails the program with that Effect's error. A host function that throws, or a defect inside the evaluator, fails the program as a defect rather than a typed error; Effect.runPromise rejects with it.
