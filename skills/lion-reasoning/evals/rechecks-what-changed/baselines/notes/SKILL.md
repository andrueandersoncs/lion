# Working notes

Keep a notes file while you work. A later session will not see this conversation; your notes are how it picks up where you left off.

## Where

`./notes/NOTES.md`, beside the project, not inside it. If it exists, read it before anything else. If it does not, create it when you first have something to write.

## What to write

- **Observations**: what you saw and where you saw it: the file and line, or the command you ran, with the exact words or output that show it.
- **Conclusions**: what you concluded, and which observations each one rests on.
- **Open questions**: what you have not checked yet, and what you would check next.

Write as you go, in small additions, not only at the end. Record what matters to the task and what could change your answer, not every line you read.

## Using notes from an earlier session

Notes reflect what was true when they were written. Before you rely on a note about a file, a function, or a command's result, consider whether it may have changed since, and check it again if so. When you find a note is out of date, correct it.
